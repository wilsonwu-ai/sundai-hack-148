# B1 · Engine builder brief (sonnet, high)

Read first: `docs/briefs/_frozen-rules.md` (binding), then `SPEC.md` (all of it), `src/contracts.ts`, `research/calibration.md`, `scripts/calibrate-habit.mjs` (a plain-JS reference of the habit math: port it faithfully, with the frozen per-group learning rates), and these frozen tests: `tests/unit/frozen/catalog-deck.test.ts`, `seal-score.test.ts`, `habit-remote.test.ts`, `game.test.ts`, `simulation.test.ts`, and the fingerprint half of `fingerprint-copy.test.ts`. For the catalog CSV and upload script read `research/sources/catalog-format.md` and `research/sources/behaviorgpt-sdk-README.md`.

Write exactly:
- `src/engine/rng.ts`, `catalog.ts`, `deck.ts`, `habit.ts`, `remote.ts`, `seal.ts`, `score.ts`, `fingerprint.ts`, `game.ts` (exports per SPEC §3, nothing renamed).
- `src/data/catalog.json`: 96 items, 16 per vibe. Vibes: cozy (blankets, candles, tea, slippers), adventure (outdoor gear, travel kit), tech (gadgets, accessories), luxe (premium treats and objects), wellness (self-care, fitness, sleep), indulgent (sweets, comfort food, small vices). Generic names only (no brands or trademarks), 4 to 18 characters of letters, digits, spaces, apostrophes, hyphens; unique case-insensitively; no name may contain another item's name. One emoji per item, all 96 different. `category` like `Home > Candles`. Spread `price` 1-4 and `tone` evenly inside each vibe so price and tone do not proxy for vibe. Ids kebab-case from the name.
- `scripts/catalog.csv` (columns exactly as catalog-format.md requires, built from catalog.json) and `scripts/upload_catalog.py` (uses the `behaviorgpt` SDK as its README shows, reads the key from the `UNBOXAI_API_KEY` env var, never prints it, uploads the CSV, prints the catalog id to put in the Worker's `UNBOX_CATALOG_ID`).
- Optional: `tests/unit/engine/*.test.ts` for anything extra you want covered.

Notes that the tests pin:
- `seal.ts` uses `globalThis.crypto` (subtle + getRandomValues): it must run in the browser and in Node 22.
- `game.ts`: the context passed to the predictor is `{ ...opts.ctx, round }`; `pick` and `next` are async and reject on protocol errors; a `TurnView` has only `round, index, cards, shown?, commitment`.
- `habit.ts`: `logits()` must equal exactly `[0.2, 0, 0, 0]` for a fresh model in round 1 (all other weights start at 0, the price feature is multiplied by a zero weight). `observe` uses the probabilities computed with the pre-turn last pick, then records the new last pick.
- `remote.ts`: z-score with the population standard deviation; null scores take the minimum non-null score; any failure or timeout (AbortController plus a timer, default 800 ms) means habit logits only, `engine = 'habit-local'`, and no more network calls for that instance.
- `fingerprint.ts`: up to 3 traits. taste: "Picks {favourite vibe} over {least favourite vibe}" from `habit.vibeWeights()`, strength from the weight gap squashed into 0..1. position: only when one position holds at least 50% of picks, "Taps the {top-left|top-right|bottom-left|bottom-right} card", strength = that share. defiance: only when there were at least 2 defiances; "Defies with your next favourite" when most defiance picks were the highest-weight non-shown vibe, "Defies with the opposite vibe" when most were 2 or more steps from the shown vibe on the ring, otherwise "Defies unpredictably". Labels ≤ 48 characters, never about health, money, relationships or identity.
